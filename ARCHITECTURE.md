## 1. High-Level Overview

```
┌─ DATA SOURCE ──────────────────────────────────────────────────────┐
│                                                                    │
│  Synthetic provider + vendor data                                  │
│  generated by 01_historical_data_generation.sql                    │
│                                                                    │
│  PROV  PROV_ADDR  PROV_COMMUNICATION  PROV_TAXONOMY                │
│  PRV_XREF  PRV_XREF1  VENDOR  VENDOR_ADDRESS                       │
│  VENDOR_PROVIDER_REF  VENDOR_TAXONOMY                              │
│                                                                    │
└──────────────────────────┬─────────────────────────────────────────┘
                           │ seeds
                           ▼
              ┌────────────────────────────┐
              │  PROD_RAW_DB.ORACLE         │
              │  (authoritative source)     │
              │                            │
              │  PROD_RAW_DB.PUBLIC         │
              │  tasks + procedures         │
              │  (never cloned)             │
              └────────────┬───────────────┘
                           │
              DAILY_CLONE_REFRESH task
              re-clones ORACLE schema daily
                    │              │
          zero-copy clone   zero-copy clone
                    │              │
                    ▼              ▼
         ┌──────────────┐  ┌──────────────┐
         │ DEV_RAW_DB   │  │ TEST_RAW_DB  │
         │   .ORACLE    │  │   .ORACLE    │
         └──────┬───────┘  └──────┬───────┘
                │                 │
                └────────┬────────┘
                         │ dbt transforms
                         ▼
          DEV / TEST / PROD_ANALYTICS_DB
            STAGING · INTERMEDIATE · MARTS
```

`PROD_RAW_DB.PUBLIC` holds the tasks and stored procedures. Because the daily re-clone operates at the schema level (`ORACLE` only), `PUBLIC` is never touched — the pipeline infrastructure stays in PROD only.

## 3. dbt Model Layers

```
┌─ Source  (PROD_RAW_DB / DEV_RAW_DB / TEST_RAW_DB) ─────────────────┐
│  schema: ORACLE                                                    │
│                                                                    │
│  PROV  PROV_ADDR  PROV_COMMUNICATION  PROV_TAXONOMY                │
│  PRV_XREF  PRV_XREF1  VENDOR  VENDOR_ADDRESS                       │
│  VENDOR_PROVIDER_REF  VENDOR_TAXONOMY                              │
└────────────────────────────┬───────────────────────────────────────┘
                             │
                             ▼
┌─ Staging ──────────────────────────────────────────────────────────┐
│  materialization: VIEW   schema: STAGING                           │
│                                                                    │
│  stg_oracle__providers           ← PROV                            │
│  stg_oracle__vendors             ← VENDOR                          │
│  stg_oracle__vendor_provider_ref ← VENDOR_PROVIDER_REF             │
└────────────────────────────┬───────────────────────────────────────┘
                             │
                             ▼
┌─ Intermediate ─────────────────────────────────────────────────────┐
│  materialization: TABLE   schema: INTERMEDIATE                     │
│                                                                    │
│  int_provider_addresses      joins provider + address data         │
│  int_provider_taxonomy       joins provider + taxonomy data        │
│  int_provider_communication  joins provider + communication data   │
│  int_provider_xref           joins provider cross-reference data   │
└────────────────────────────┬───────────────────────────────────────┘
                             │
                             ▼
┌─ Marts ────────────────────────────────────────────────────────────┐
│  schema: MARTS                                                     │
│                                                                    │
│  dim_provider                                                      │
│    materialization: INCREMENTAL (merge)                            │
│    unique_key: provider_id                                         │
│    picks up rows on or after the current max last_modified_date    │
│                                                                    │
│  fct_provider_county_summary                                       │
│    materialization: INCREMENTAL                                    │
│    unique_key: [county, provider_type]                             │
│    re-aggregates affected groups on each run                       │
└────────────────────────────────────────────────────────────────────┘
```

## 4. Daily Task Pipeline

```
8:00 AM MT (America/Denver)
          │
          ▼
┌─ DAILY_DATA_INSERT  (root task) ───────────────────────────────────┐
│  Calls INSERT_INCREMENTAL_DATA()                                   │
│  Inserts per run:                                                  │
│    ~75  rows → PROV                                                │
│    ~50  rows → VENDOR                                              │
│    ~100 rows → VENDOR_PROVIDER_REF                                 │
│  All rows stamped: LAST_MODIFIED_DATE = CURRENT_DATE()             │
└────────────────────────┬───────────────────────────────────────────┘
                         │ on success
                         ▼
┌─ DAILY_CLONE_REFRESH  (child task) ────────────────────────────────┐
│  Calls REFRESH_DEV_TEST_CLONES()                                   │
│                                                                    │
│  CREATE OR REPLACE SCHEMA DEV_RAW_DB.ORACLE                        │
│    CLONE PROD_RAW_DB.ORACLE                                        │
│  GRANT USAGE  ON SCHEMA DEV_RAW_DB.ORACLE  TO DEV_ANALYTICS_RL    │
│  GRANT SELECT ON ALL TABLES IN SCHEMA ...  TO DEV_ANALYTICS_RL    │
│                                                                    │
│  (same pattern for TEST_RAW_DB)                                    │
└────────────────────────────────────────────────────────────────────┘

9:00 AM MT (America/Denver)  — after data insert + clone refresh complete
          │
          ├──────────────────────────┐
          │                         │
          ▼                         ▼
┌─ DAILY_DBT_TEST ───────────┐  ┌─ DAILY_DBT_PROD ───────────────────┐
│  EXECUTE DBT PROJECT        │  │  EXECUTE DBT PROJECT               │
│    DBT_FULL_DEMO            │  │    DBT_FULL_DEMO                   │
│    ENVIRONMENT = 'test'     │  │    ENVIRONMENT = 'prod'            │
│  Writes to TEST_ANALYTICS_DB│  │  Writes to PROD_ANALYTICS_DB       │
└─────────────────────────────┘  └────────────────────────────────────┘
```

All four tasks live in `PROD_RAW_DB.PUBLIC`. The dbt project object lives in `DEV_ANALYTICS_DB.PUBLIC.DBT_FULL_DEMO`, backed by the `DEV_ANALYTICS_DB.PUBLIC.DBT_FULL_DEMO_REPO` Git repository object.

## 5. RBAC Summary

```
┌─ Role Hierarchy ───────────────────────────────────────────────────┐
│                                                                    │
│  SYSADMIN                                                          │
│    └──► DEV_ANALYTICS_RL ──► read/write  DEV_ANALYTICS_DB          │
│                               read       DEV_RAW_DB.ORACLE         │
│                                                                    │
│  TEST_ANALYTICS_RL ────────► read/write  TEST_ANALYTICS_DB         │
│                               read       TEST_RAW_DB.ORACLE        │
│                               (CI/CD only — future phase)          │
│                                                                    │
│  PROD_ANALYTICS_RL ────────► read/write  PROD_ANALYTICS_DB         │
│                               read       PROD_RAW_DB.ORACLE        │
│                               (CI/CD only — future phase)          │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
```

`DEV_ANALYTICS_RL` is granted to developers directly (via `03_analytics_env_setup.sql`). `TEST_ANALYTICS_RL` and `PROD_ANALYTICS_RL` are reserved for CI/CD service accounts — developers cannot write to test or prod analytics databases.

SYSADMIN owns all raw databases and the task/procedure objects in `PROD_RAW_DB.PUBLIC`, enabling it to run the daily pipeline without elevated privileges.

## 6. Quick Reference

| Term | What It Means |
|---|---|
| `PROD_RAW_DB.ORACLE` | Authoritative source data; seeded by script 01, grown daily by the task pipeline |
| `PROD_RAW_DB.PUBLIC` | Holds tasks + procedures; never cloned into DEV/TEST |
| `DEV/TEST_RAW_DB.ORACLE` | Zero-copy clones of PROD — production-quality data, no storage cost until they diverge |
| `DAILY_DATA_INSERT` | Root task; fires 8am MT; inserts ~225 records into PROD |
| `DAILY_CLONE_REFRESH` | Child task; fires after insert; re-clones ORACLE schema into DEV and TEST |
| `dim_provider` | Incremental model; merges on `provider_id`; picks up rows on or after watermark |
| `fct_provider_county_summary` | Incremental aggregate; re-aggregates county + provider_type groups that had changes since last run |
| zero-copy clone | Instant schema copy with no storage cost until data diverges |
| `--full-refresh` | Rebuilds all models from scratch; required in DEV/TEST after each re-clone |
| `env_var()` in dbt | Reads `DBT_CURRENT_ROLE`, `DBT_DATABASE`, `DBT_WAREHOUSE`, `DBT_SOURCE_DB` at runtime |
